## Build and free-tier budget

Checked October 23, 2026 against [Vercel limits](https://vercel.com/docs/limits) and [Hobby quotas](https://vercel.com/docs/plans/hobby): direct CLI source uploads are limited to 100 MB and 15,000 files. Build output can contain more files. Hobby includes 100 GB Fast Data Transfer, 10 GB Fast Origin Transfer and 1,000,000 CDN requests; exceeding Hobby quotas can pause the relevant feature until its quota window resets. These are team-wide limits, not a guarantee of unlimited free hosting. This personal study project uses Hobby without a paid upgrade.

The full question payload is 448,733,781 bytes in 21,006 locked files (20,980 WebP images, 25 PNGs, and questions.js). `questions.js` is about 31 MB raw and 5.58 MB with gzip; production also serves Brotli. Image data is already compressed. An uncached full-bank visit plus selected question images consumes transfer, and every asset request counts toward CDN requests. Monitor Vercel Usage; exact capacity depends on caching, runs, assets per question and bot traffic. Hundreds of megabytes of stored build output do not themselves consume monthly delivery transfer until requested.

`.vercelignore` excludes question payloads, PDFs, recordings, caches and credentials from CLI input; initial source upload is about 3.6 MB and 59 files. `tools/build-static.mjs` fetches the immutable public GitHub snapshot named by `asset-lock.json`, extracts the payload during build, and verifies every file's SHA-256 and length before copying into `dist/`. Windows question-bank CRLF is normalized to the committed LF bytes. There is no runtime GitHub dependency for Vercel assets. Build failures keep the previous production deployment intact.

For a changed question bank, first commit/push imports; then regenerate `node tools/lock-assets.mjs <full-committed-sha>`, commit the lock, and deploy. The lock must refer to a publicly fetchable commit. Do not include credentials in it. A local build can use `DOSPREP_OUTPUT_ROOT=D:/Codex/DosPrepMigration` to stage outside a full C: drive. Normal Vercel builds use their local `dist/`.

## Old URLs and local browser data

`migration.json` controls the GitHub Pages transition. Until `enabled` is true and `verifiedDeployment` is recorded, `tools/build-pages.mjs` publishes the existing app with no redirects. After activation, old HTML URLs use a browser migration gate. GitHub Pages cannot issue configurable server-side 301/308 responses: this uses client-side redirects, new canonicals, and noindex/follow on the old HTML. Page paths, query strings and room-code hashes map to the same path at the new origin.

An empty browser redirects automatically. Stored DosPrep data or offline status pauses the redirect and presents Move browser data, Download full browser backup, or Stay on the old site. A restricted, nonce-bound popup handshake sends only DosPrep study data and preferences to the exact new origin using postMessage. It never puts study data or auth tokens in URL parameters, analytics, or a server-side transfer store. The destination merges guest histories, flags, highlights, account-keyed backups, cloud ledgers/pending revisions, queued answer events, reading size, analytics consent and Project Pulse browser preference/ID. It retains a full incoming backup and acknowledges only after storage succeeds. Quota failure rolls back destination writes. Source data is never erased; if it changes during transfer, the old tab stops and requests another transfer. Account backups stay keyed by UID until the matching account signs in. Existing event IDs retain the normal replay protection; historical history imports do not backfill statistics.

Anonymous live-room identities cannot move between browser origins. The gate links those users to `legacy/live.html#ROOMCODE` on the old origin, retaining their existing auth persistence and room access. Recovery copies of all original HTML pages live under `/reading-rush/legacy/` and use the same old-origin JS, assets and Firebase backend. New visitors can follow old room-code links to the new origin. Keep the old GitHub Pages site, scripts, assets, and Firebase authorized domain available so people with old unsynced data or ongoing rooms can recover them. Do not blindly replace the old site with meta-refresh pages or delete its assets.

On Vercel, the migration notice links back to the old browser-data gate. A full `dosprep-browser-migration-*.json` file can also be restored at `/migration.html`. Backups contain private study records; keep them private. Ordinary practice exports differ from full browser migration bundles and can still be restored through the practice app's existing Restore progress control.
